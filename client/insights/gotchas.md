## Tests

- **Mock a hook from its real initial value (e.g. `useRunEvents` → `running: false` on the first render) and flip it as the hook does; a mock that is "live" from the first render hides mount-render bugs.** — spot it: a drawer/panel fix green in tests that misbehaves only right after mount in the browser. — [INSIGHTS: 2026-10-15 — a hook mock that starts in the "live" state hides first-render bugs](../INSIGHTS.md#2026-10-15--a-hook-mock-that-starts-in-the-live-state-hides-first-render-bugs)
- **There is no `@testing-library/user-event` in this package — write interaction tests with synchronous `fireEvent`, not `userEvent.setup()`.** — spot it: a new test's `user-event` import fails to resolve, in a repo where every other RTL idiom works. — [INSIGHTS: 2026-09-18 — there is no `@testing-library/user-event` here; use `fireEvent`](../INSIGHTS.md#2026-09-18--there-is-no-testing-libraryuser-event-here-use-fireevent)
- **Import only types from `@devdigest/shared` in `client/`; mirror a needed constant locally.** A value import makes Next bundle the vendored index, whose `.js` specifiers webpack can't resolve — every page using it 500s in `next dev` while typecheck and vitest pass. `src/lib/shared-type-only-imports.test.ts` guards it. — spot it: `Module not found: Can't resolve './contracts/…js'` from `src/vendor/shared/index.ts`. — [INSIGHTS: 2026-10-12 — a value import from `@devdigest/shared` 500s every page in `next dev`](../INSIGHTS.md#2026-10-12--a-value-import-from-devdigestshared-500s-every-page-in-next-dev-while-typecheck-and-vitest-stay-green)
- **When overriding one export of a shared hooks barrel with `vi.mock`, spread the real module first via `importActual` — the bare factory form replaces every export.** — spot it: a test fails inside a component or hook it never named, deep in the render tree (e.g. a mocked `lib/hooks/reviews.ts` crashing `FindingsPanel`). — [INSIGHTS: 2026-09-23 — `vi.mock` of a hooks barrel breaks children, and the error names the child](../INSIGHTS.md#2026-09-23--vimock-of-a-hooks-barrel-breaks-children-and-the-error-names-the-child)
- **When `getByText` reports multiple matches on i18n copy, check whether the two UI states mean the same thing before widening the query.** — spot it: RTL's `Found multiple elements with the text: …` on a string reused across more than one empty/error state — usually a copy bug, not a query bug. — [INSIGHTS: 2026-09-22 — `getByText` finding "multiple elements" is usually a copy bug, not a query bug](../INSIGHTS.md#2026-09-22--getbytext-finding-multiple-elements-is-usually-a-copy-bug-not-a-query-bug)

## UI

- **To wait for a resource that 404s until written (e.g. a run trace), use `retry: false` + a function `refetchInterval` bounded by a deadline; `retry: false` alone never re-fetches.** Every observer of the key polls. — spot it: a drawer stuck on "no trace" right after a run ends. — [INSIGHTS: 2026-10-15 — polling for a resource that 404s until it is written](../INSIGHTS.md#2026-10-15--polling-for-a-resource-that-404s-until-it-is-written-refetchinterval-as-a-function-keeps-going-with-retry-false)
- **Adding a nav item to `src/vendor/ui/nav.ts` is the one sanctioned hand-edit of vendored UI — record it in the spec that asks for it and comment the line, since a vendor refresh silently drops it.** — spot it: a new route only reachable by typing its URL, with no NAV/SETTINGS_ITEM extension point anywhere downstream. — [INSIGHTS: 2026-09-22 — `vendor/ui/nav.ts` is the one vendored file we edit, and the edit is disposable](../INSIGHTS.md#2026-09-22--vendoruinavts-is-the-one-vendored-file-we-edit-and-the-edit-is-disposable)
- **An editor that PUTs the whole list back must not render its controls until the stored list has loaded — early-return `Skeleton` on `isLoading` and `ErrorState`+retry on `isError`.** — spot it: the first toggle on a freshly opened tab replaces every stored link with one. — [INSIGHTS: 2026-10-05 — a list editor backed by a replace-all PUT, rendered before its data loads, wipes the stored list](../INSIGHTS.md#2026-10-05--a-list-editor-backed-by-a-replace-all-put-rendered-before-its-data-loads-wipes-the-stored-list-on-the-first-click)
- **Render model/untrusted Markdown through a `react-markdown` wrapper with `disallowedElements={["img"]}` and `skipHtml`; the vendored `Markdown` renders remote images and regex stripping is bypassable.** — spot it: `<img src=http…>` in a component that shows LLM text. — [INSIGHTS: 2026-10-05 — stripping Markdown images with regexes is bypassable](../INSIGHTS.md#2026-10-05--stripping-markdown-images-with-regexes-is-bypassable-disallow-img-in-the-renderer)
- **An overlay that must escape a PR-list row or a card (a hover card, or a vendored `Modal`, which does not portal itself) needs `createPortal` into `document.body`; a hover card also needs `position: fixed` from `getBoundingClientRect()`, flipped above the trigger near the viewport bottom.** — spot it: a popover silently cut off at a row's edge, or sibling cards painting over a modal opened from a `FindingCard`. — [INSIGHTS: 2026-09-18 — a popover inside the PR list must portal; the table clips it](../INSIGHTS.md#2026-09-18--a-popover-inside-the-pr-list-must-portal-the-table-clips-it)
- **`SeverityBadge compact` (vendored `@devdigest/ui`) shows the icon only, never the severity word — render the word yourself (or drop `compact`) when a design needs it, and assert the word in a test.** — spot it: a card or stub meant to read "⚠ WARNING …" shows just the icon, while tests that only check the title stay green. — [INSIGHTS: 2026-09-27 — `SeverityBadge compact` renders the icon only, never the severity word](../INSIGHTS.md#2026-09-27--severitybadge-compact-renders-the-icon-only-never-the-severity-word)
- **In a colocated `styles.ts`, give every entry its own literal with `satisfies CSSProperties`; never spread a separately typed base object into entries (dynamic values become function entries).** — spot it: `TS2742: The inferred type of 's' cannot be named without a reference to '.pnpm/csstype@…'` on a styles file that looks like all the others. — [INSIGHTS: 2026-09-27 — TS2742 from a `styles.ts` that spreads a separately typed base object](../INSIGHTS.md#2026-09-27--ts2742-from-a-stylests-that-spreads-a-separately-typed-base-object)
- **When only one side of a border differs, write all four sides longhand (`borderTopColor`/`borderRightColor`/`borderBottomColor`/`borderLeftColor`, same for width) — pairing a shorthand like `borderColor` with one longhand side still mixes shorthand and longhand.** — spot it: React's `Updating a style property during rerender` warning firing only after an interaction changes the value on an already-mounted node, never on first paint. — [INSIGHTS: 2026-09-18 — "Updating a style property during rerender" survives the obvious fix](../INSIGHTS.md#2026-09-18--updating-a-style-property-during-rerender-survives-the-obvious-fix)

## Tooling

- **For a targeted client test run use `pnpm exec vitest run <pattern>`; `pnpm test -- <pattern>` runs the whole suite (`vitest run -- <pattern>` ignores the pattern).** — spot it: a "targeted" run reports `Test Files 42 passed (42)` instead of the one file you named. — [INSIGHTS: 2026-09-27 — `pnpm test -- <pattern>` does not filter; it runs the whole suite](../INSIGHTS.md#2026-09-27--pnpm-test----pattern-does-not-filter-it-runs-the-whole-suite)
- **A vitest filter containing a bracketed route segment (`[repoId]`) matches no files, even escaped — filter on a bracket-free substring (`context/`).** — spot it: "No test files found, exiting with code 1" for a path that plainly exists. — [INSIGHTS: 2026-10-05 — a vitest path filter containing `[repoId]` matches no files](../INSIGHTS.md#2026-10-05--a-vitest-path-filter-containing-repoid-matches-no-files-even-escaped)
- **Never run `pnpm build` while `next dev` is serving the same `client/`; it rewrites `.next` and the dev server returns 500 until restarted.** — spot it: every page 500s right after a build step. — [INSIGHTS: 2026-10-05 — `pnpm build` while `next dev` runs](../INSIGHTS.md#2026-10-05--pnpm-build-while-next-dev-runs-breaks-the-dev-server-500-on-every-page)
- **Wrap every page that calls `useSearchParams()` in a `<Suspense>` boundary regardless of whether `pnpm build` currently complains — it only fails on routes it actually prerenders.** — spot it: check the `○` (static) vs `ƒ` (dynamic) column of the `pnpm build` route table; a dynamic route with no boundary builds clean today and breaks the day it becomes static. — [INSIGHTS: 2026-09-22 — the `useSearchParams`/`Suspense` rule only bites on STATIC routes](../INSIGHTS.md#2026-09-22--the-usesearchparamssuspense-rule-only-bites-on-static-routes)
