## DB & migrations

- **A nullable column added to a unique index stops deduplicating every row where it's NULL**, because Postgres treats NULLs as distinct values in a unique index. Index `coalesce(<col>, '')` and make the lookup query use the same expression. — spot it: two rows that should be the same (e.g. two self-managed hosts of the same repo) both insert successfully instead of the second one conflicting. — [INSIGHTS: 2026-09-23 — adding a NULLABLE column to a unique index silently stops deduplicating](../INSIGHTS.md#2026-09-23--adding-a-nullable-column-to-a-unique-index-silently-stops-deduplicating)
- **`pnpm db:generate` can hang forever with no output** when a single schema diff both drops and adds columns on the same table — drizzle-kit's rename-detection prompt renders nothing and reads no stdin. Split the change into two `db:generate` runs: one with only the deletion, then one with only the additions. — spot it: the command never exits and produces a zero-byte log; it looks like a hung DB connection but the same config generates fine before and after. — [INSIGHTS: 2026-09-22 — `pnpm db:generate` hangs forever when one table both drops and adds a column](../INSIGHTS.md#2026-09-22--pnpm-dbgenerate-hangs-forever-when-one-table-both-drops-and-adds-a-column)
- **A Drizzle `text(name, { enum: [...] })` column has no SQL constraint at all** — it's a TypeScript-only narrowing; the DDL is a plain `text NOT NULL`. Adding a value to one of these enums is a code-only change (edit the shared contract + schema literal, mirror to the client copy); don't write or expect a migration for it. — spot it: `pnpm db:generate` produces nothing for an enum-value addition. — [INSIGHTS: 2026-09-21 — a Drizzle `text(..., { enum })` column has NO constraint in SQL](../INSIGHTS.md#2026-09-21--a-drizzle-text--enum--column-has-no-constraint-in-sql)
- **A foreign-key column carries no index of its own** — Postgres indexes the column a FK points at, never the column holding it, so `.references()` alone leaves a filter on that column unindexed. Add `index('<table>_<col>_idx')` in the schema's callback yourself whenever you add a read path over a FK column. — spot it: `WHERE child.parent_id = ANY($1)` sequential-scans the whole child table despite `parent_id` looking fully wired. — [INSIGHTS: 2026-09-18 — a foreign-key column carries no index; every child-rows query scans](../INSIGHTS.md#2026-09-18--a-foreign-key-column-carries-no-index-every-child-rows-query-scans)
- **Migrations are never applied on boot.** Run `pnpm db:migrate` after cloning and after any pull that adds a migration; `pnpm db:seed` afterwards is idempotent. — spot it: the API boots fine, then every DB-backed route 500s with a missing-relation error. — [INSIGHTS: 2026-09-17 — `relation "…" does not exist` on a fresh checkout](../INSIGHTS.md#2026-09-17--relation--does-not-exist-on-a-fresh-checkout)

## Tests

- **Never read `run_traces` straight after `waitForPrRuns` returns.** The executor writes the trace document after marking the run terminal, and `waitForPrRuns` returns silently on timeout instead of throwing — poll `GET /runs/:id/trace` until it's 200 **and** `prompt_assembly` is present, then throw on your own timeout. — spot it: a test that passes alone but fails in the full `.it.test` lane with `Cannot read properties of undefined (reading 'skills')`. — [INSIGHTS: 2026-09-21 — `waitForPrRuns` returns before the run trace exists](../INSIGHTS.md#2026-09-21--waitforprruns-returns-before-the-run-trace-exists)
- **`MockGitHubClient` lists exactly one hard-coded PR** unless the caller passes `opts.pulls`, and `seed()` persists that same PR. To exercise a second PR, insert it yourself (`db.insert(t.pullRequests)`) or construct the mock with `{ pulls: […] }` — don't assume a list-endpoint test exercised more than one. — spot it: an assertion about "the other PR" (no review / skipped by rollup) fails on a `toBeDefined()` that looks like a route bug. — [INSIGHTS: 2026-09-18 — `MockGitHubClient` lists exactly one PR, so "the other PR" doesn't exist](../INSIGHTS.md#2026-09-18--mockgithubclient-lists-exactly-one-pr-so-the-other-pr-doesnt-exist)

## Security

- **A field that lets the caller *disambiguate* among trusted values must never be able to *add* one.** Validate the host against the allowlist first and let the hint only choose among what survives; also reject non-http(s) schemes explicitly (`z.string().url()` passes `file:`/`ftp:`, and `new URL('file:///x').origin` is the literal string `'null'`). — spot it: an unknown-host request is accepted because the body also names a `provider`, and a credential (e.g. a GitLab PAT) then goes to that host. — [INSIGHTS: 2026-09-23 — an optional "disambiguation" field turned into an authorisation bypass](../INSIGHTS.md#2026-09-23--an-optional-disambiguation-field-turned-into-an-authorisation-bypass)
- **A `..` traversal guard placed after `new URL()` never fires**, because the WHATWG URL parser normalises `..` segments out of the path before the guard can see them — the input just silently resolves to a different, well-formed target. Keep such guards on the raw-string branches (e.g. a self-managed base-URL match) that don't go through `new URL`, and assert the normalising behaviour itself so a later rewrite can't quietly reopen the hole. — spot it: a test asserting `parseRepoUrl('.../acme/../../etc/passwd')` throws fails — nothing throws, because `.pathname` is already `/etc/passwd`. — [INSIGHTS: 2026-09-23 — a `..` guard placed after `new URL()` never fires](../INSIGHTS.md#2026-09-23--a--guard-placed-after-new-url-never-fires)
- **A `realpath` containment check must resolve the allowed root too, not just the target**, then compare on the separator boundary (`p === root || p.startsWith(root + sep)`) rather than a bare `startsWith` on raw strings. — spot it: an otherwise-correct symlink guard rejects every file once the allowed directory is itself behind a symlink (e.g. macOS `/var` → `/private/var`, exactly what `mkdtemp(tmpdir())` produces), which reads like the guard catching a real escape rather than a path-spelling mismatch. — [INSIGHTS: 2026-09-22 — a `realpath` containment check must resolve BOTH sides, or it fails closed](../INSIGHTS.md#2026-09-22--a-realpath-containment-check-must-resolve-both-sides-or-it-fails-closed)

## Tooling

- **An HTTP adapter without an SDK must throw an error carrying a numeric `status`** (`Object.assign(new Error(msg), { status: res.status })`) or pass its own `opts.isRetryable` — otherwise `withRetry` silently retries nothing, because `fetch` resolves instead of throwing on 4xx/5xx and `defaultIsRetryable` classifies purely by `err.status`/`err.statusCode`/`err.response.status`. — spot it: a hand-rolled `fetch`-based adapter wrapped in `withRetry(() => withTimeout(...))` looks fully resilient but never retries a 429 or a 502. — [INSIGHTS: 2026-09-23 — `withRetry` is a silent no-op for an adapter built on raw `fetch`](../INSIGHTS.md#2026-09-23--withretry-is-a-silent-no-op-for-an-adapter-built-on-raw-fetch)
